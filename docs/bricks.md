# Features

A feature is a part of the app that lives in a folder of its own: a view, a card, an input or a panel. The app finds every folder under `ui/src/bricks/`, so adding a feature is adding a folder: no list, registry or app file to edit. Each can be switched on or off while the app runs, on the Features page (Features, in the top bar). A builder makes one against one file, `ui/src/bricks/contract.ts`, in the playground (`ui/bricks.html`), without the core, a key or the rest of the app.

In code a feature is still a "brick": its folder is `ui/src/bricks/<id>/` and its manifest is `brick.json`. <!-- names-ok: code name -->

## A feature's folder

```
ui/src/bricks/<id>/
  brick.json   what the Features page shows, and how the feature starts
  index.tsx    the feature: a React component, its default export
  …            anything else it needs (its CSS, helpers), inside the folder
```

| `brick.json` | |
|---|---|
| `id` | The folder's name: lowercase letters, digits and dashes. |
| `name` | What the Features page calls it: a word or two (24 characters at most). |
| `does` | One line for a person: what it does (90 characters at most). |
| `kind` | `view`, `card`, `input` or `panel` (below). |
| `defaultOn` | On in every browser until someone switches it off. A new feature starts `false`. |
| `demoSafe` | `true` when it's fine to switch on live in front of people: it works on an empty map and a full one, needs no setup, and asks for nothing (the camera, the mic) before a click. The Features page folds the rest under "Not for the demo". |
| `flag` | Optional. `?<flag>` in the address switches it on for that visit (`?level`). `?bricks=<id>,<id>` does the same for any feature by its id, flag or none. |
| `showsLiveWords` | Optional. `true` when it shows `map.partial` (your words as you say them) itself: while it's on, the bottom bar leaves out its big live line, so the words never show twice. Tiny transcript does. |

Where each kind shows:
- **view**: another way to see the map. Its name joins the Cards and Pictures switch, and it shows in the map's place, padded clear of the bottom bar as the Pictures view is.
- **card**: a small card in the bottom bar, above the input box, where the Unfinished thought card shows. Its height counts with the bottom bar's cards, so a thought just shown moves clear of it. The template is one.
- **input**: a new way in (gestures, a pedal). It mounts with the page, draws at most a small mark of its own, and acts through `actions`.
- **panel**: floats over the page and places itself. The Level meter is one.

## How the app finds them

`ui/src/bricks-core.ts` reads every `./bricks/*/brick.json` (at once: they're small) and every `./bricks/*/index.tsx` (lazily) with Vite's `import.meta.glob`. Folders whose name starts with `_` are skipped: the template is copied, not run. A feature's code loads only once it's on, so a feature that's off costs the page its `brick.json` and nothing else. A feature whose `brick.json` is wrong is left out with a warning in the console; `scripts/bricks-check.mjs` says the same, in the same words, before a merge.

`ui/src/BrickSlot.tsx` mounts each kind in its place, every feature behind a boundary of its own: one that throws shows "… stopped working" with a Switch it off button, and the rest of the page carries on.

## The contract

`ui/src/bricks/contract.ts` is the only app file a feature imports. Its default export gets `{ map, actions, on, brick }`:
- `map`, the map as it is now, read-only: `threads` (a comment's carries `anchor`, below), `thoughts`, `active` (your topic), `suggestions`, `reminders` (proposed reminders and events), `apps`, `notes` (why a thought went where it went), `points` (each topic's point count, as its card shows it), `rooms` (the color of each topic and its tangents), `topics` (below), `positions` (what someone placed by hand on a canvas, by topic or thought id: absolute canvas coordinates of its top-left, by whom, when; nothing for the rest), `speakers` (everyone on the map by the name their thoughts carry, each `{ ai }`: true for an AI participant, the AI helper), `me`, `partial` (your words as they're heard, not yet final: what the bottom bar's live line shows while you talk, "" between turns; only yours, and only in the tab whose mic is on), `connected`, `jobs` (the AI helpers' jobs, below). The types are the app's own, from `core.ts`, `positions-core.ts` and `annotate-core.ts`. A new snapshot comes with every change, and with every word heard: the arrays in it stay the same objects, so work kept on them (`useMemo` on `map.thoughts`) isn't redone per word.
  - **Comments:** a comment is a tangent anchored to words: a topic under the point's topic whose thoughts are the comment and its replies, with `anchor: { thought_id, quote }`, the words it's tied to. A view shows it beside those words; the Cards view shows it as a tangent.
  - **Reading:** `map.readThrough` is the newest turn you've read, shared by Talk and the Canvas, or null before reading. The position is kept in this browser and sent to the call, including on reconnect.
  - **✓ Agreed:** a thought everyone on the shared map agreed on will list who in `agreed_by`; the core doesn't say who yet, so none has it.
  - **Jobs:** a helper's work as the core relays it (`core/src/guide.rs`; `ui/src/work-jobs.ts` keeps it): `{ id, title, status, result?, parent?, demo, by, at_ms, started_ms?, ended_ms? }`, `status` being `running`, `done`, `failed` or `waiting` (`result` is what a done job found, why a failed one stopped, the question a waiting one asks). The same `id` again is the same job in a new state; `map.jobs` lists each once, in the order it first came (the newest 60), and a window that joins is replayed them, so a feature switched on late has them all. `started_ms` and `ended_ms` are only what this window saw (the `at_ms` of the first running and the first ending), so a job it met already over has no length; `demo` marks a simulated one, which whatever shows it must say. Jobs belong to the connection, never to the saved map.
  - **Themes:** a theme is a group of top-level topics that belong together; on screen it's always "theme" (what the code calls a `thread` is a topic on screen), while the code keeps the name `topic` for the theme. `thread.topic` is the theme a topic is under, by name (a tangent has its top-level topic's; none until it's sorted), and `topics` lists every theme, `{ name, threads }` (`threads`: how many top-level topics), in the order they first come among the topics. The core's AI names them (6 at most, two or three plain words) once the map has 4 top-level topics with points, and sorts each new top-level topic within a minute (core `topics.rs`); a person's rename or move is theirs, never undone by it. A view that colors by theme takes a theme's place in `topics` as its color, so views agree.
- `actions`: `addThought(text)` (as if typed in the input box), `openThread(id)` (as a picture in the Pictures view does: back to the Cards view at that topic, highlighted; your place moves there), `select(id)` (that topic is "this" for what's said next, as pointing at its card makes it), `notify(text)` (one line in the notice lane), `position(id, x, y)` (a topic's card or a thought's point placed there for every window, kept within ±1,000,000; both null: back to the view's own layout; call it on every step of a drag: steps go at most once a frame, and your own come back in `positions` with `by` you), `listen(on?)` (a tap on the mic: `true` on, `false` off, nothing switches it; it starts the mic only inside a click or key press in this tab, so a feature never turns it on by itself). Each answers on screen as its button does.
  - `annotate(thoughtId, quote, text)`: a comment by you on `quote`, words picked in that thought's point, for every window. The first on those words starts their comment, a later one answers in it; both come back in `threads` and `thoughts` as placed (no model reads a comment). False when it can't go (no words, over 6,000 characters, the core away); the core refuses one whose point left the map, and says so.
  - `openCatalog(id?)`: the Features page, as the Features button opens it; with a feature's id, at its row, marked, its switch focused.
  - `readThought(thoughtId)`: a thought shown long enough to read advances the shared Talk/Canvas position. Older thoughts never move that position back. The read feature can separately move its topic's bookmark back when tapped.
  - `hint(text, target?)`: one line (140 characters at most) beside the part named `target` with an arrow at it, as another participant's point shows, or in the corner without one; your feature's name on it, in this window only. `target` is a `data-guide` name: the app's (docs/guide.md) or one the feature gives its own part. False when nothing showed.
  - `renameTopic(from, to)`: theme `from` is called `to` for every window (spaces as one, 40 characters at most); a name already there, in any case, makes the two one. `moveToTopic(threadId, topic)`: that topic's top-level topic, with its tangents, goes under theme `topic` for every window. Both say false when they can't go (no name, the same name, the core away); the core says why when the theme or topic has left the map. In the app they go straight to the core (ui/src/topics-core.ts), so `App.tsx` passes neither; the playground answers them as the core would.
- `on(name, listener)`, or `useBrickEvent(on, name, listener)` in a component:
  - `landed`: a thought just placed, `{ thoughtId, threadId, mine, model, ms, by }`: `model` the model that placed it ("Muse Spark 1.3"; null when a rule did, or this window didn't hear which), `ms` how long placing took, from said to landed (the point's own time), `by` who acted: `{ kind: "brick", id, name }` when a feature's `addThought` added it in this window, else `{ kind: "person", name }`.
  - `words`: your words as they're heard, each time they change (as `map.partial` then); "" once the turn ends or the mic stops.
  - `loudness`: the mic's level, 0 to 1, every 320 ms while it's on.
  - `notice`: a notice or map update as this window shows it, a repeat too: `{ text, kind, time }`, `kind` being `notice`, `error` or `map-change`.
  - `pointing`: what the guide's arrow points at (another participant's point, or a feature's hint), `{ target, by, thoughtId?, threadId? }` (a point's topic too), or null once it's down: a view dims the rest once, never twice.
  - `asked`: something you asked for by voice or typing that a feature answers, only in your windows: `{ what: "notices" }` is "what just happened?". It never lands on the map.
  - `speaking`: in a call, someone took the floor or gave it back, `{ speaker, on, mine }` (yours too, `mine`): the core's word from their live words (`core/src/call.rs`), never the words themselves, which come with the turn's thought as it ends. Alone, never.
- `brick`: its own `brick.json`.
- `map.usage`: allowances from the core's `USAGE_FILE` (`updated`, `rows`) and its own rolling-hour model budget (`calls: { used, limit, at_ms }`). Null with no readable file or while disconnected; refreshed every 60 seconds and never journaled. The playground supplies null. Usage hides when null; [Architecture](ARCHITECTURE.md#usage-allowances) documents the file's shape and `core/src/usage.rs` reads it.

Three conventions come with the page:
- An element marked `data-thread={id}` is "this" while pointed at or focused (`this-card.ts`), so "rename this to …" works on it without calling `select`.
- A feature styles only its own classes, each starting with its id (`.template`, `.template-open`), with the app's tokens (`--bg`, `--card`, `--ink`, `--muted`, `--line`, `--accent`, `--amber`, `--ai`, `--room-<color>`, `--shadow`), so it reads right in light and dark. It never draws a `<header>`: the app's is the page's only one.
- A feature names a part of its own for a hint, or the guide, with `data-guide`, starting with its id (`data-guide="tiny-transcript"`, `"tiny-transcript:size"`); a view marks the map's topics and points with theirs (`thread:<id>`, `point:<id>`), as the Canvas does.

The contract grows by a line: a new field or action is added to `contract.ts`, and its source to `bricks-core.ts`, `BrickSlot.tsx` and `App.tsx` (and the playground). Every feature depends on that file, so that's the hub's change, not a builder's.

## Slots

The page's regions, each an element marked `data-slot="<name>"` while it's on screen (`SlotName` and `SLOTS` in `contract.ts`). A feature finds one by name (`document.querySelector('[data-slot="stage"]')`), to draw beside or in it, or keep clear of it. A region can be absent in a layout or view; the names stay. The shell in `ui/src/shell/` is the default page, read once before rendering; `?shell=1` opens the classic page (the header and bottom bar it replaced), kept for one more release.

| Slot | The region | Today |
|---|---|---|
| `top-left` | the wordmark and the map's name | Shell (default): `TopLeft`'s fixed corner, with the map name and mode stamp; the wordmark hides on a populated phone view. Classic page (`?shell=1`): the header's `.brand`. |
| `top-right` | Find, Features, people | Shell (default): `TopRight`'s fixed corner with Find on a populated map, Features, Share controls and enabled import/export controls. Classic page (`?shell=1`): the header's `.header-actions`. |
| `bottom-left` | the camera: following, zoom stops | Shell (default): App marks Back to the Canvas here in other views; the Canvas puts its camera at the left on a wide canvas, in the shared shelf row when narrow, without this marker. Classic page (`?shell=1`): no marker; the Canvas's camera sits above its shelf at the right (a shared row when narrow). |
| `bottom-right` | the shelf, and the held stack above it | Shell (default): App's `.shell-br` wrapper holds the held stack above the separately mounted Canvas shelf, or at the bottom right without a shelf. Classic page (`?shell=1`): no marker; the Canvas positions its shelf at the right. |
| `stage` | bottom center, with space beside it: the input box, captions, one notice | Shell (default): App's `.shell-stage`, at most 600 px wide, holds cards, one notice or map update, the `#shell-caption` host and the input box; History suppresses the stage notice and map update. Classic page (`?shell=1`): no marker; the bottom bar spans the window's width. |
| `status` | the status line: the mic, its time, live words, what's waiting | Shell (default): `StatusLine`, a 24 px line at the bottom with mic state/time, Tiny transcript's live words and pending/queued/saved status; its right side opens History. Classic page (`?shell=1`): the header's `.status`. |
| `rail` | the panel at the right: Talk, History, Features, Settings | Shell (default): the shell's `Rail` while a tab is open, a right panel or phone sheet; outside a call its Talk tab uses `TalkTurns`. In a call the shell omits Talk and `TalkRail` separately marks its own open call rail or phone sheet with this name. Classic page (`?shell=1`): absent. |
| `shelf` | what you keep at hand | Both layouts: the Canvas's `Shelf`, while that view is mounted; at the right on a wide canvas, in the corner row when narrow. The shell's bottom-right wrapper does not own it. |

| `slot:<thought id>` | where a thought on its way will land | Both layouts: marked by the view that shows it (the Canvas's dashed slot or arriving point); a fly-in aims there. |

A fly-in under way marks its bubble `data-flight="<thought id>"` (Fly-in), so a view can wait for it to arrive. A view that mounts after its thought landed (the Canvas, with the map's first topic) looks for the marks when it mounts, and the bubble waits for it.

## On and off

The Features page lists every feature by kind, each with its name, its line and its switch; features that aren't `demoSafe` fold under "Not for the demo". A switch acts at once and only in this browser: what was switched is kept in `localStorage` (`e2a2o.bricks`), every other feature follows its `defaultOn`, and other windows of the same browser follow along. A view switched off while it's shown hands the window back to the Cards view.

## The playground

`ui/bricks.html?brick=<id>&sample=<name>` mounts one feature as the app does, against a map from `samples/` replayed through the window's own reducer (`sample=empty` for none). Every feature is there, the template too. What the feature asks for is answered as the app would (a thought it adds lands on the topic you're on 1.2 s later, placed by Muse Spark 1.3 as its route says; `openThread` moves your place; a comment comes back as the core's changes would) and logged on the right, with what it heard under it. "Add a thought", "Talk, then shout" and "Show a notice" fire `landed`, `loudness` and `notice`; "Say a thought" says one: its words come in `map.partial` and `words` one at a time (a word every 250 ms), then, at the turn's end, the thought lands; "The AI helper says one" has an AI participant join and say a thought; "Helper jobs" plays a simulated helper's jobs (one running with a side job, one done, one asking, one failed) as the core relays them; "Point at a topic" fires `pointing` (again: null); "Ask what just happened" fires `asked`; "Someone speaks" fires `speaking` (Maya on, then off 1.5 s later); "Core away" sets `map.connected` to false. In the console, `brickActions` is the shown feature's own actions, to try one by hand.
- While building: `cd ui && npm run dev`, then open `http://localhost:5173/bricks.html?brick=<id>`; it reloads on every save.
- Built: `npm run build` builds it after the app, into `ui/dist`, and the core serves it at `/bricks.html` on this laptop.

## A builder's rules

1. Copy the template: `cp -R ui/src/bricks/_template ui/src/bricks/<id>`, then put your id where "template" is, in `brick.json`, `index.tsx` and the CSS (its file name and every class).
2. Stay in your folder. Import only `../contract`, React, Motion and, for a canvas (pan, zoom, drag), React Flow (`@xyflow/react`, MIT, and its `dist/base.css`). A new package, a model or a field in the contract is the hub's call: ask. Runtime models must be Meta's (the hackathon's rule).
3. Start off: `defaultOn: false`. Set `demoSafe: true` only once it works on an empty map and a full one, at a phone's width, and asks for nothing before a click.
4. Work in the playground: a full map, the empty one, a phone's width and dark mode (DevTools emulates both).
5. Done when `node scripts/bricks-check.mjs <id>` passes, after `cd ui && npm run build`.

`scripts/bricks-check.mjs` holds: every folder's `brick.json` (the app's own rule) and default export; imports (only `../contract`, React, Motion, React Flow and the folder's own files; no `<header>`; a `data-guide` name of its own starts with its id); CSS (every selector names one of the feature's classes, keyframes too, and every class styled is used); `contract.ts` takes only types from the app, and its slot names are this page's; each feature mounts in the built playground on a full map, an empty one and at a phone's width, with no error and nothing running off the side. The contract itself, in the playground: `landed` with its model, time and who (a person, or the feature that added it), `words` as they grow, `pointing`, `asked`, `speaking`, a comment and its reply, `openCatalog`, a hint and one refused; in the app: the slots on today's layout (no stage on today's bottom bar), a comment from the core tied to its words in the Canvas, "what just happened?" opening Notification history (off: a notice says where to switch it on, and the view stays), and Notification history's clock clear of Tiny transcript's line on a phone. Run for all features, it also checks the app: at their defaults features add nothing to the first screen; the Features page lists every feature; each view feature, switched on, joins Cards and Pictures, shows in the map's place and hands back to Cards; a switch survives a reload; `?level` still shows the Level meter. A planted breach of each folder rule is caught, so the check can't pass by missing one.

## Talk preset

Say or type **talk mode**, switch **Talk** on in Features, or open `?preset=talk`.
Talk keeps the Canvas (including comments and Stay here), the bottom input and mic,
live words, captions, notices and Usage. Usage still appears only when the core supplies it.
Other feature switches are covered by the preset; their saved choices are left untouched.
Say or type **all features** to leave Talk and restore those choices. Talk survives reload;
leaving also removes `preset=talk` from the address so it stays off on reload.
